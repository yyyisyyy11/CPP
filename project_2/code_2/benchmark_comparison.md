# Dot Product Benchmark: Original (long long) vs No-overflow (int)

> [!NOTE]
> **Original**: 整数类型使用 `long long` 累加器 + `(long long)` 强制类型转换，防止溢出  
> **No-overflow**: 整数类型使用 `int` 累加器，无扩展转换，允许溢出  
> 浮点类型（float/double）两个版本完全一致，无变化

## 核心结论

| 场景 | int 提升 | short 提升 | char 提升 |
|------|---------|-----------|----------|
| C (no-opt) | ~1.0× | ~1.0× | ~1.0× |
| **C (O3)** | **~1.0×** | **3.6×–8.0×** | **2.2×–6.5×** |
| Java | 1.4×–1.7× | ~1.0× | ~1.0× |

> [!TIP]
> **最关键的发现**: O3 下，`short` 和 `char` 去掉 `long long` 后性能提升最大（高达 8×），因为编译器可以在 SIMD 寄存器中打包更多窄类型元素进行并行计算。`int` 类型差异不大，因为 32-bit 乘法+累加本身与 64-bit 累加的向量化宽度差异较小。
